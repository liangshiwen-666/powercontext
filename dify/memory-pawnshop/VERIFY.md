# 验证样例 · VERIFY

> 目标：让评审在 10~15 分钟内按步骤体验完整玩法，并能核对 Dify 与 PowerContext/seekdb 的实际作用。
> 前置：按 README 完成 Step 0~5，在 Dify 应用对话窗口开始。

## 0. 初始状态与恢复

**初始状态（seed 之后）**

| scope | 内容 |
| --- | --- |
| `档案柜`（`archive`） | 28 条档案（镇志 7 / 账本 8 / 讣告 5 / 传闻 8） |
| `npc/ayuan` | 3 条记忆（「没回去」「娘说别回来」「梦见过三楼的灯」） |
| `npc/laozhou` | 3 条记忆（「晚到二十分钟」「算错了时间」「码头一个人也没有」） |
| `npc/baitang` | 4 条记忆（「第一次来」「见山在门口站一会儿」「这盏灯见过很多次」「在别处等过一个人」） |

**恢复到初始状态（二选一）**

```bash
# A. 只清空并重建数据（scope id 不变）
python3 scripts/seed_pc.py --reset

# B. 彻底重建（含 seekdb 数据目录）
docker compose -f docker-compose.yaml -f docker-compose.game.yaml down -v
COMPOSE_PROFILES=postgresql docker compose -f docker-compose.yaml -f docker-compose.game.yaml up -d
python3 scripts/seed_pc.py
```

**开新一局**：在对话里输入 `重开`（游戏状态清空；但 NPC 的记忆保留——这正是跨会话设定）。

## 1. 第一局 · 阿沅（新手关，C01）

**初始条件**：新会话，`状态` 为空；输入 `开门`。

**操作与预期**

| # | 输入 | 预期表现 | 技术核对点 |
| --- | --- | --- | --- |
| 1 | `开门` | 旁白 + 阿沅开场白（“我娘走的那天，我没回去”），下方出现当铺菜单 1/2/3 | Dify 执行 IF/ELSE 的 advance 分支；会话变量 `state` 初始化 |
| 2 | `查 2003 年卫生院` | 返回 1 条主档案（应为 A-03 卫生院夜班交接簿：23:44 家属到院），可能附带 1~2 条相关；然后阿沅顺着一句台词；信任略升 | HTTP 节点 `POST /v1/atomic-memory/search` 检索 `archive` scope，返回 `matched_by` 含 `text`/`vector` |
| 3 | `追问：你那天在袜厂加班到几点` | 阿沅动摇，说漏“王婶那晚也在走廊” | 检索 `npc/ayuan` scope（命中原有的“没回去”记忆） |
| 4 | `上酒 回甘 A`（A = 「花要养着」） | 上酒 → 写入 memory 成功（显示 scope=npc/ayuan、memory_id、`存本 revision = R1`）→ 醒神台词（会提到“花要养着”“别难过”一类）→ 判定“他信了” → 菜单变为「开票」 | HTTP 节点 `POST /v1/memory/remember`；返回 `artifact.revision=1` |
| 5 | `开票` | 当票卡片：票号 `WH-20261027-C01-AYUAN-R1`、记忆库 `npc/ayuan`、存本 `R1`、当物摘要、金额、信任/怀疑；随后阿沅结算台词；菜单变为「开门」 | Code 节点计算金额；再次写入一条「当票」记忆（跨会话证据） |

**判定效果**：此时进入 PowerContext Dashboard 或执行
`python3 scripts/pc_smoke.py` 的检索片段，可看到 `npc/ayuan` 下新增了「花要养着」+「当票 WH-…」两条 active 记忆。

| # | 输入 | 预期表现 | 技术核对点 |
| --- | --- | --- | --- |
| 1 | `开门` | 白棠开场：“第一次来。……您这铺子，二十年没换过灯吧，灯光不行。” | 客人 scope `npc/baitang` |
| 2 | `查存根簿` | 返回 A-02 存根簿：239 张同款当票，第 240 页空白 | 档案检索 |

| 4 | `上酒 回甘 A`（A = 「替我看好灯」） | 写入 R1；醒神台词；判定 | |
| 5 | `开票` | 第三张当票 | |
| 6 | 自动 | 三张票后输入 `开门` 触发结局（S/A/B/C/D 之一），点题句出现 | Code 节点 `_ending` |

**跨会话验证（本作品关键验收点）**

1. 完成阿沅一局（上酒 + 开票）后，**刷新页面/新建一个对话**（不要在旧会话里继续）。
2. 输入 `开门`，选择阿沅那局；观察她是否自然提起上一次被塞的记忆（“我昨夜梦见我娘了……是不是我记错了？”）。
3. 打开 PowerContext 的检索记录/Dashboard：`npc/ayuan` scope 中仍保留上一局写入的「花要养着」与「当票 WH-…」两条记忆（`active` 状态），说明记忆跨会话保存与召回均生效。

**遗忘（inactive）验证**

在任意一局输入 `把那段抹了`（或使用当铺菜单的抹除项）：
- 系统提示“她想起那段的时候，会先愣一下，像踩空一级台阶”；
- 之后的检索不再命中该条，但 `npc/<id>` 的列表中它仍在（state=`forgotten`）——对应 PowerContext 的 `inactive` 语义，不是物理删除。

## 4. 无 Dify 时的逻辑验证（可离线跑）

如果只想核对游戏逻辑与 PowerContext 集成、不启动 Dify：

```bash
python3 scripts/verify_game.py
```

该脚本会：
1. 读取 `DSL/memory-pawnshop.yml`，抽出所有 Code 节点并按依赖顺序执行；
2. 调用真实 PowerContext（`PC_BASE` 默认 `http://127.0.0.1:17429`）完成检索与写入；
3. 走完「开场 → 2 轮追问 → 上酒 → 开票」×3 位客人 → 结局，并打印当票与最终状态。

期望输出结尾：

```
【结局 S·灯】
记忆不是用来骗的。它是用来在雾里认出彼此的。
当票 3 张｜档引 N 条｜余银 X 元｜评级 Y 分
```
