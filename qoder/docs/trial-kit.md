# 知返 · 5 人试用与效果记录手册

用于收集「使用效果」材料。原则：**只记录真实发生的使用**，不补写、不外推；数字附上导出文件或截图。

## 1. 试用前准备（组织者，约 10 分钟）

1. 按 README 第 5 节启动应用，确认本机 <http://127.0.0.1:8080> 可用，并已完成一次 `scripts/verify.py`。
2. 让同一局域网内的同学访问时，重新以「监听所有网卡」启动：
   - Windows PowerShell：
     ```powershell
     $env:APP_HOST="0.0.0.0"
     powershell -ExecutionPolicy Bypass -File scripts\start.ps1
     ```
   - WSL / Linux：在 `.env` 加 `APP_HOST=0.0.0.0` 后 `bash scripts/start.sh`。
3. 用 `ipconfig`（Windows）或 `hostname -I`（Linux）查本机局域网 IP，把 `http://<IP>:8080` 发给同学；只放行 8080 端口，**不要做公网端口映射**。
4. 每位同学在页面顶部「使用者」填自己的代号（如 `trial-01`），彼此记忆互相隔离；每人使用同一套示例笔记即可。

> 仅使用示例笔记或不含隐私的学习资料；不要上传个人账号、身份证件、公司内部文档。

## 2. 每位同学的 10 分钟任务

| 步骤 | 操作 | 期望看到 |
| --- | --- | --- |
| 1 | 资料页点「导入示例笔记」 | 2 个文件 / 8 个片段 |
| 2 | 提问：`页面置换算法里 LRU 和 Clock 有什么区别？` | 回答 + 引用列表（文档 / 章节 / `chunk_id` / 分数） |
| 3 | 在「Clock 算法」相关引用下点「标记没懂」，填写 `Clock 为什么能近似 LRU` | 出现形如 `art_…@r1` 的记忆编号 |
| 4 | 再提一个问题（或刷新后重问） | 回答中出现「记忆」区块，并标注召回来源 |
| 5 | 复习计划页点「生成计划」 | 计划包含该薄弱点，并列出引用的 `artifact_id@revision` |
| 6 | 证据页查看「检索与使用记录」 | 提问 / 检索 / 写入记忆计数增加，最近检索有 `chunk_id` 与耗时 |

记录时间：任务开始、结束各记一次（手机计时即可）。

## 3. 反馈表字段

可直接复制为问卷或聊天提问，逐人收集：

```text
代号（可匿名）：
日期 / 设备：
1. 以前回答这类问题或整理复习要点，大约需要多少分钟？
2. 用知返完成同样任务，大约用了多少分钟？
3. 引用（文档 / 章节 / chunk_id）是否让你更愿意相信答案？ 1–5 分
4. 下次提问能召回「没懂」的记忆，对复习是否有帮助？ 1–5 分
5. 是否愿意继续使用？ 是 / 否 / 不确定
6. 一句话评价（请保留原话）：
   是否同意在比赛材料中公开引用（可匿名）： 是 / 否
7. 遇到的问题或希望改进的地方：
```

效率写法：分别列出每人的前后耗时，报告中位数与人数（如「5 人中 4 人从约 20 分钟降到 8 分钟」），不要只给一个平均数。

## 4. 可核对的数据来源

| 材料 | 获取方式 |
| --- | --- |
| 使用人数、提问 / 检索 / 记忆写入次数、平均耗时 | 证据页；或 `GET /api/evidence` |
| 每次检索的关键词、命中片段、分数、耗时 | `GET /api/evidence`；`GET /api/export/events.csv` |
| 记忆编号与状态 | `GET /api/memories?user_key=trial-01` |
| 计划引用的记忆 | `GET /api/plan?user_key=trial-01` |
| 界面证据 | 问答 / 计划 / 证据页截图（含使用者代号与时间） |

建议新建 `docs/trials/` 保存：

- `usage-YYYYMMDD.csv`（证据页导出的原始文件）
- `trial-01-answer.png`、`trial-01-plan.png` 等截图
- `feedback.md`（反馈原话与统计，公开前按同意情况匿名化）
