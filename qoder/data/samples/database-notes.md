# 数据库系统 · 课堂笔记

## 事务与 ACID

事务是数据库操作的逻辑单元，包含 ACID 四个性质：原子性、一致性、隔离性、持久性。原子性由 undo 日志保证，持久性由 redo 日志保证。事务的提交点是指事务日志写入磁盘的那一刻，而不是内存中数据页刷新的时刻。

## 并发异常与隔离级别

并发事务可能引发三类异常：脏读（读到未提交数据）、不可重复读（同一行两次读结果不同）、幻读（同一范围两次读行数不同）。SQL 标准定义了四个隔离级别：读未提交、读已提交、可重复读、串行化。MySQL InnoDB 默认是可重复读，并通过间隙锁（next-key lock）减少幻读。

## 死锁与等待图

死锁检测使用等待图：把每个事务看作一个节点，如果事务 T1 在等待 T2 持有的锁，就从 T1 向 T2 画一条有向边。当等待图中出现环时，说明存在死锁。注意边的方向是「等待者指向持有者」，这是最容易记反的地方。

检测到死锁后，数据库通常选择回滚代价最小的事务作为牺牲者。InnoDB 使用 wait-for graph 并定期检测，也可以通过 innodb_deadlock_detect 参数控制。

死锁预防则通过破坏四个必要条件之一：互斥、请求并保持、不可剥夺、循环等待。常见策略有一次封锁法（一次性申请全部锁）和顺序封锁法（所有事务按同一顺序申请资源）。

## 索引与 B+ 树

B+ 树的非叶子节点只存储键值，叶子节点存储数据并按照键值顺序用双向链表连接，因此非常适合范围查询。相比 B 树，B+ 树的非叶子节点能容纳更多键，树高更低，磁盘 IO 更少。

聚簇索引的叶子节点直接存放整行数据，二级索引的叶子节点存放主键值，因此通过二级索引查询非覆盖列时需要回表。覆盖索引是指查询所需的列都在索引中，可以避免回表。

最左前缀原则：联合索引 (a, b, c) 能支持 a、a+b、a+b+c 的查询，但不能直接支持 b 或 c 开头的查询。
